# 05 童鞋素材、Prompt 与真实 Demo

## Demo 是验收用例

用新前缀 `V1-DEMO-KIDS-*`，category=kids_shoes、mode=demo。
不使用办公椅、童装或真人儿童。不仿造已授权商品、不声称 TOPSTAR 官方原图。
同一双白色/浅蓝色虚构童鞋贯穿候选，避免 3 张变成 3 双不同商品。
不把旧的广告图、功能文字、尺寸和认证当真实商品事实。

## 素材链

1. 原生 Worker 独立生成透明商品源：`product_rgba_v1.png`。
2. 校验真实 alpha，保留主体、鞋带、边缘；透明棋盘图不等于 alpha。
3. Python 叠到白底，得到 `product_white_v1.png`，标记 derived-from 商品源。
4. 分别生成户外、室内、摄影棚 3 张背景；每次一张完整独立图。
5. 同一商品源按冻结几何参数合成到背景，得到 3 张候选；严禁总拼图裁切。
6. 记录 source → background → composite → candidate 的 hash 和处理参数，回写飞书。

透明图给合成用，白底图给人看和商品卡片用。这是两个文件角色。
白色童鞋不允许用“删除接近白色的像素”自动抠图；会删掉鞋本身。
原生工具没有透明能力时先验证编辑/分割方案，不能伪造 alpha。费用和再调用计入同一预算。
默认不强加随机阴影：模型背景光源、机位、支撑面和商品视角必须匹配，再用可解释脚本处理。
技术检查通过不代表视觉自然，最终人审仍必需。

## 调用预算

第一次 live 集成最多 6 次图片工具调用：商品源 1、背景 3、修正或能力探针最多 2。
白底派生、合成、下载和 ZIP 不计图片调用。文本规划 Token 和开发 Subagent 消耗单列。
默认一调用一输出；如果服务会内部二次生成而无法约束，报告预算定义和不可控部分。
失败/unknown 占预算；不得以新建 run_id 规避本次项目级授权上限。
原生订阅用量未知时填 `cost_amount=null`，不能记 0 元。

## Prompt 构建

用户选组件：商品/用途/风格/场景/构图/光线/约束。
编译器先按固定版本排序、变量检查和冲突检查，再得到视觉 Prompt + 治理快照。
同样输入与版本应得相同编译文本和 hash；创意规划为独立 AI 节点，输出也冻结。
禁止用任意 eval/Jinja 执行用户字段；只用受限模板与允许变量。
保留最终 Prompt 快照，库中主要维护组件和已发布模板。

Prompt_reference 只可重用经许可的人工描述。不得先自动解读一张禁止输入的图，再把描述作为规避路径。
Image_reference 真正传图时必须校验 mode、来源、allow_image_generation 和不可变文件 hash。
缺省为拒绝；false/空值不能等价 true。

## 图片质检

自动检查：可解码、大小/像素限制、透明有效性、画幅、文件唯一性、角色与任务匹配、实际输出数量。
AI 初筛：构图、文字/Logo、鞋体完整性、场景差异、背景与主体接触自然度，输出问题而非最终批准。
人工审核：风格是否符合预期、主体是否像同一商品、边缘和光影是否能接受。
本次 Demo 不作真实材质、健康功能、防滑、认证、年龄或尺码声明。

## 必须留的证据

真实调用事件与 ID，未报告模型写 not_reported；不能凭用户口头的“Image 2.5”标签强写版本。
原始生成图、必要处理后的透明源、白底派生、3 个背景、3 个候选均单独编号。
PNG 全部单图。最终交付包只收审核批准的 Candidate，不把中间背景当成品凑数量。
