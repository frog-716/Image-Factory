# 09 验收与交付

## 三种成功要分开

PACKAGE_REFERENCE_PASS：本包离线代码可跑，证据在 evidence/。
PROJECT_INTEGRATION_PASS：现役项目增量开发、旧回归保留、实际接口兼容。
LIVE_DEMO_PASS：本机真实调用、真实飞书记录/附件/人审/交付/数据回流通过。
AUTONOMOUS_RUNTIME_PASS：无需开发主控 Thread 逐步发指令，运行器真正推进并恢复。

前一项不能替代后一项。

## V1 硬验收清单

- B0 项目现状和备份可追溯，不破坏 RUN-001/002/003。
- 真实 Sol/Luna 配置记录；不可用时明确报告，没有伪造 Subagent。
- 固定 Workflow 独立于聊天，节点能被替换为 mock 验证调度。
- Native Worker 真实调用和返回文件；L2 自动能力实测或明确 BLOCKED。
- 童鞋透明源 1、白底派生 1、独立背景 3、独立合成候选 3。
- 6 次授权上限含全部能力验证/修正；无 API 回退。
- 每張图片都有真实文件、hash、角色、输入链、Prompt/Workflow 版本和产出证据。
- 人在飞书极简入口提交/审图/取交付，无需手写 prompt 或复制节点结果。
- Demo 人审没有伪真实商品/品牌声明；不自动代审。
- ZIP 集合精确等于批准集合，round-trip hash 一致，驳回图不存在。
- 模拟 Usage/指标有来源和明确标记，二次导入 existing；生产查询排除。
- 最终飞书状态与 Runtime 一致，未同步时明确 pending_sync。
- 重启不重复生图/上传；unknown 不能盲重试。
- 全量旧项目测试和新增测试分别记录；未运行项标 NOT_RUN。
- 用户教程写明开机/运行器在线条件和实际不可用能力。

## 视觉验收

三张都必须是完整单图，不能把总览裁出图块。
童鞋主体一致，边缘完整，无营销功能字样和假认证。
户外、室内、棚拍可一眼区分；画面清爽，商品主次明确。
人可驳回任意数量；不要强制 A/B通过 C驳回来表演安全性。

## 交付物

项目内真实源码、入口脚本、版本化 Workflow/Prompt、飞书字段与页面配置记录。
`docs/development-v1/FINAL-REPORT.md`、`HANDOFF.md`、`STATUS.json`。
`docs/USER-GUIDE.md`：只保留启程序、选任务、审图、拿图、停/继续、看错误六个动作。
保留一份测试/生成/读回/审核/交付证据索引；不把所有日志放进面向用户的交付 ZIP。
可重复使用的 Starter 手册与问题定位卡，用户无需再粘贴长恢复 Prompt。

## 完成的措辞

“已建设核心并通过离线测试；headless 原生生图未验证”是明确中间状态。
“已全自动跑通”必须有关闭开发对话后的证据。
“实测 3 张候选，用户批准 N 张并交付 N 张”比虚构完成率百分比更有意义。
