# 04 飞书平台与极简人工流程

## 日常只有四个入口

1. 选商品与素材：看图片卡片，选 SKU。商品事实与素材来源可展开。
2. 发起任务：选用途/场景/风格/数量；高级区可改 Prompt 组件和步骤，默认收起。
3. 审核图片：大图 + 通过/退回 + 原因，详细检查在同一页面，不让用户去找另一张表。
4. 领取交付：批准图片 ZIP、实际图片数、模式标签、生成/审核时间；详情可以反查每一步。

V1 先复用商品卡片、素材画册、生产看板和审图台，再做一个入口页连接它们。
页面能力须核实租户和 CLI；缺少页面 API 时交付精确的一次性网页配置教程，不编造命令。
如果应用模式确实可用且减少点击，可增量配置；不强制引入 BaseApp token 或新的后台系统。
浏览器或本地预览不是飞书真正上线页面，验收时必须区分。

## 发起任务表单

默认展示：商品、图片用途、消费场景、视觉风格、数量、提交。
自动或从模板带入：当前用户、任务版本、默认生产路径、预算、画幅、mode。
“高级设置”：组件替换、参考素材、构图、光线、允许改动、预算上限。
禁止将版位当作拍摄场景；默认无价格/功能/认证宣称。
发布的模板必须版本化。用户所见“提交”会产生任务意图，运行器确认接单后显示运行状态。

## 审核语义修正

生产审核：商品准确、品牌与渠道检查、人工确认、审核人及结论。真实依据缺失就不通过。
Demo 审核：视觉适合本次演示、仅限演示用途、人工确认、审核人及结论。
Demo 两个检查不能通过在原因里加免责语来替代真正不同的字段语义。

角色：审核身份从用户真实操作/可信身份字段提取，不允许 Agent 填入用户名字模拟人审。
审核必须绑定 task、asset_version、sha256、review_policy_version。
最新有效事件覆盖旧结论；撤回会使未交付候选失效。已交付后撤回需标记交付作废/告警，不能暗删历史。
“待审核数”从当前候选最新有效审核派生，不能数历史审核行数。

## 人工最少几次操作

开工时一次设置任务与调用预算；有默认模板后无需每轮读长 Prompt。
首轮 Demo 生成源图和背景由系统完成。人工最后看 3 张图并分别做决定。
批准时勾清楚适用范围，别为了测试规定必须 A/B 通过。驳回路径用离线测试验证。
审完后无需再发“继续导出”长提示词，运行器定期读取审核并继续。

## 权限与误操作

现役同一个 user 身份不是强权限隔离。禁止声称靠提示词就能阻止同账号写审核。
V1 单人本地试用可明确记录此风险；团队/真实经营上线前需独立执行身份或权限隔离方案。
审核字段不能让执行 Worker 写；Gateway 生产方法使用字段白名单，审核同步只读。
页面不展示密钥、token、临时鉴权 URL，日志入口只展示脱敏摘要。

## 仪表盘与自动化

轻量生产概览值得做：待生成/待审核/待交付/阻断/运行器在线状态。
以 Runtime 计算后的候选与任务汇总投影为数据源，先修 RUN-002 一类状态不同步问题。
没有真实经营数据时，经营页明确空状态；Demo 数字必须醒目标注模拟并默认排除正式统计。
自动化仅提醒或更新用户意图，不自动批准、不盲重试、不和 Runtime 竞争状态。
通知去重键由 run_id + event_id 构成，失败保留日志，不影响已完成图片或触发重新生产。
