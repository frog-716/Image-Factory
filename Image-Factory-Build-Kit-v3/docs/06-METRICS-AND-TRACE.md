# 06 可追溯数据与指标口径

## 对象和关系

SKU 1:N 商品源版本；Asset N:M Run（通过显式输入/输出关系）；Run 1:N StepRun；StepRun 1:N Attempt。
一个图片字节 hash 可以被多个合法任务复用；资产去重键应含命名空间/业务角色，不在整个库盲目只按 SHA 合并。
Run N:1 WorkflowVersion；PromptSnapshot 绑定组件版本、变量和生成计划。
Candidate 绑定 run/slot/asset_version；Review 为追加事件；Delivery 绑定审核快照与批准图片集合。
Usage 绑定 asset_version + channel + account + placement + creative/ad/page id + 有效时间段。
同一张图用于两个广告，需要两个 Usage。Metric 关联 Usage 和统计窗口/口径/来源版本。

## 最小血缘查询

给定 ZIP 内任一图片，必须返回：
源商品与 source_hash → 输入参考/许可 → Workflow 与组件版本 → 完整 Prompt/hash → 工具调用与实际模型 → 原始输出/hash → 合成参数 → Candidate → 最新审核/身份/范围 → ZIP/hash → Usage → 指标/原始来源。

给定指标记录，反向查询同一条链。无法单图归因时填“不可归因”，不能把广告组总数平均分给每张图。

## 运行指标

- 任务等待/执行/人工审核/上传耗时分别记录，不混成模型耗时。
- 图片调用：请求、已预留、成功、明确失败、未知、修正次数。
- 候选数量、唯一图片数、有效批准数、驳回数、待审核数、最终交付数。
- 审核通过率 = 最新有效批准候选数 / 已完成有效审核候选数。待审不算分母。
- 交付率 = 有有效交付的任务数 / 完成生产且进入评审的任务数；统计期和任务状态必须明确。
- 成本有账单证据才填数值，未知填 null；含币种、计费依据与订阅/API 标记。
- 每次重试保存父 Attempt，不覆盖失败记录。

## 经营指标

曝光、点击、收藏、加购、订单、支付/成交、收入可为空。0 表示真实观察到零，null 表示未知。
CTR = 点击 / 曝光；曝光为 0 或未知时结果 null。
每点击订单率 = 订单 / 点击；不能直接命名成万能 CVR。若采用会话转化率，明确订单/会话或购买会话/会话。
收入必须有币种及退款口径；ROAS 需要广告花费与归因收入，缺任何一个不计算。

每行必须记录：Usage、日期起止、时区、渠道/账号/版位、归因窗口、定义版本、数据性质、原始证据 SHA。
Clicks>impressions、orders>clicks 可能来自口径差异，先标记可疑与核查，不静默截断或删除。
不要仅凭 CTR 高断言卖货更好；价格、人群、位置、预算、时段都可能改变结果。
同 SKU 不同图的比较需要对照设置及最小样本规则，由业务另行确定。

## 幂等与修订

同一 Usage/窗口/口径/来源 hash 重复导入 → existing。
同一来源 hash 但数值不同 → 冲突，不覆盖。
真实来源修订 → 新 revision 保留旧版，查询取有效版；不能把累计快照当独立日增量累加。
浮点 API 读回的整数 40.0 与 40 要规范化；bool、NaN、负数、非整数计数拒绝。
组合身份、资产 hash、时间窗口、字段类型必须在远端读回时做语义标准化。

## 隔离

mode 为 demo/production 枚举，缺失模式拒绝，不使用“名称带 DEMO”作唯一过滤。
严格正式查询应为 mode=production，不是 `demo != true`；缺失标记也不能漏进正式数据。
Demo 指标全部 data_nature=simulated。只有来自真实后台并带证据的 observed 才能入正式口径。
本包参考 MetricBook 为离线内存示例；真正 live 幂等键和修订必须在现役数据库持久化。
