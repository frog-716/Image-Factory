# 五分钟上手

## 1. 下载和放好
下载 `Image-Factory-Build-Kit-v3.zip`。双击解压。
把得到的整个 `Image-Factory-Build-Kit-v3` 文件夹拖进现有 `Image-Factory` 文件夹。

应该像这样：

```text
Image-Factory/
  factory/                     原代码，保留
  docs/                        原文档，保留
  var/                         原数据，保留
  AGENTS.md                    原规则，保留
  Image-Factory-Build-Kit-v3/   新开发图纸，新增
    START-CODEX.md
    README.md
    ...
```

不要把新包里的子文件逐个覆盖到项目根目录。旧启动包留作历史，无需删除，本轮不用它启动。

## 2. 让开发工程师接手
Codex 打开原 `Image-Factory` 项目，新建一个开发对话，选 Sol，高。
当前客户端支持 `/goal` 时先启用它，再粘贴启动文字。
客户端没有目标模式时，普通对话也可以按本包目标、检查点连续开发；不得谎称已启用目标模式。

```text
读取 Image-Factory-Build-Kit-v3/START-CODEX.md，按它开发 Image Factory V1。
Sol 高负责开发主控，Luna 极高只承担开发子任务。
项目建成后由独立运行器推进流程，Codex 只做 AI/生图能力节点。
保留现有代码、飞书数据和 RUN-001/002/003，不重复初始化。
允许本轮开发所需的本地改动，以及经备份和计划约束的独立 Demo 数据写入。
本次允许使用已验证的 Codex 原生生图完成虚构童鞋验收，最多 6 次图片调用；
包含能力验证、透明商品源、背景和修正，共用这个上限。
禁止付费 API 回退、真实发布、投放、扩大权限或自动批准图片。
连续完成开发、测试和自查，只在人工审核、权限、预算或不可恢复歧义处向我提问。
```

原生图片额度属于你的账户用量。上面授权只管本次虚构童鞋 Demo，模型推理/开发对话用量另计。

## 3. 不用替 Codex 当传话筒
它先盘点、备份，再分配开发工作并集成。Luna 报告给 Sol，Sol 自己复核。
不用你为每个子任务开对话、复制结果或重复发“继续”。
同一个目标里，如果环境停止运行，需要在恢复后发：

```text
读取 docs/development-v1/STATUS.json 和 HANDOFF.md，先核对磁盘与飞书实际状态，
继续未完成开发，不重做已确认的生图、上传或记录，不放宽人工审核。
```

这些路径是本包要求开发团队在项目内建立的交接文件，未创建时以盘点阶段实际产物为准。

## 4. 轮到你时只审图
开发团队应提供一个能看到 3 张童鞋候选的入口。打开、放大、通过或退回。
Demo 页面必须说明“仅演示”，不要要求你声明真实商品准确或已有品牌授权。
AI 不可以替你审批。失败分支由自动化测试覆盖，不要求你为了凑结果故意驳回好图。

## 5. 验收产品
开发对话关闭后，用运行器从飞书提交一个新任务；程序推进，Codex 完成节点，结果回到飞书。
你审图后程序自行处理后续交付。重启电脑程序能恢复，已完成的生图不再执行。
若原生生图只能在交互会话工作，报告应明确“需要开启执行窗口”；无人值守验收保持未通过。
