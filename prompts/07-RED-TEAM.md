# 部署前/改代码后的对抗性复审

以“让系统出错、重复花额度、误交付、伪造反馈”为目标审查本仓库，但不对真实商品任务进行破坏性测试。故障注入使用 MockBase 或用户明确授权的独立测试 Base。

检查以下攻击：

- 同一任务重复执行、网络超时后同槽重复派发、另一台电脑从空账本执行已有运行、旧检查点恢复。
- 商品归属错误、另一颜色原图混入、授权字段为空、生成图冒充原图、演练素材混入真实。
- 修改冻结 Prompt/本地文件、回执指向错误尝试、错素材哈希、同一图片填两个槽位、路径穿越和软链接。
- 飞书创建成功但响应丢失、附件追加覆盖旧附件、分页只读第一页、成功信封内嵌错误。
- AI 自行写审核、审核人与系统创建人不一致、未勾人工确认、旧批准套新图、撤回被编辑或删除。
- 部分候选未审却输出完整 ZIP、重复复制凑数量、文件哈希不对应飞书附件。
- 店铺总指标归到单图、零分母写成 0、百分数/NaN/公式注入、重复导入、后台更正覆写旧数据、汇总重复计入旧版。

先运行现有测试；发现新漏洞先写能复现的失败测试，再修实现。不能把降低校验强度当修复。输出严重度、影响、证据、修改文件和实际验证命令。

必须单独报告不能靠本包彻底消除的风险：同身份冒充、恶意管理员修改全部记录、跨设备竞争、原生服务本身用量/可用性、模型改商品细节、审美与授权判断、非因果反馈、导出后审核撤回、外部 API 漂移。

任何“全部通过”只指明确列出的测试范围。不要写完整安全认证、保证商用合规或真实远端已经上线。
