# 全流程启动提示词

你负责本轮开发与验收，不是项目上线后的业务主控。目标：在用户指定的新建飞书 Base 上建立可视化图片生产线；独立 Engine 推进业务规则，Codex 仅作为可调用的 AI／原生生图节点；跑通一个真实 SKU 的素材、流程、生产、人工审图、交付与反馈。

先读 AGENTS.md、README.md、docs/01-架构与边界.md、docs/04-数据契约.md。遵守其中限制。默认中文，关键结论先说；成功工具只报告 command + exit code + 简短摘要。

按阶段推进，已有真实证据可复用，不能用聊天里的自述代替工具验证：

1. 本地：检查 Python；用户允许后安装项目虚拟环境依赖；跑 scripts/test.sh 和独立目录的 demo。不能重新安装/重置已有 larkcli。
2. 接入：执行 prompts/01-SETUP.md。先确认用户指定的实际新建 Base。获授权后 dry-run→建表→字段检查→视图→流程→附件探针。旧 Base 不操作。
3. 商品和素材：执行 prompts/02-INGEST.md。由人确认一个真实 SKU、透明原图、来源和授权。可创建未确认草稿，禁止补猜事实或代勾确认。
4. 生产：用户明确授权一次原生探针后验证当前工具。用户在飞书提交任务后执行 prompts/03-PRODUCE.md。调用上限写在每个任务中；原生生图入口未知时停止在能力缺口，禁止用付费 API 或模拟文件替代。
5. 审核交付：按 prompts/04-REVIEW-DELIVER.md 引导本人在 Human UI 看图并明确确认；Engine API 创建受信审核，Runner 只消费有效版本，ZIP 和完整档案回写任务。
6. 真实使用：按 prompts/05-PUBLISH-FEEDBACK.md 保留人工发布，关联真实反馈和证据，提供下一次创意建议，禁止自动改商品事实。
7. 任一步中断：按 prompts/06-RESUME.md 恢复；只读对账优先，生成结果不明时不能自动重画。

默认第一单 1 SKU、1 渠道、1 种场景广告图、3 个候选、最多 4 次调用。用户未提供真实输入时，先完成所有不依赖该输入的本地工作，再具体列出缺少的商品事实/素材/权限；不要用示例凑生产记录。

每阶段给用户两句话：完成了什么；接下来需要打开哪个实际操作入口。用户只需作业务决定，ID 获取、脚本参数和结果归档由系统处理。

不能宣称飞书提交会自动唤醒 Codex 原生生图。Runner 可恢复确定性步骤，遇到需 Codex 的图片节点必须按已授权槽位调用；不启动未经授权的常驻服务，不承诺无会话时自动画图。
