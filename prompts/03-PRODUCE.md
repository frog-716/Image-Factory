# 执行原生生图生产

读 AGENTS.md。只处理用户本次授权的已提交任务，单机串行。不能抢其他设备的队列。

1. 执行 `python -m factory status` 和 `queue`。对已完成任务不重画。对已有运行、已派发但结果未知的槽位先进入恢复提示词。
2. `prepare --task 实际记录ID`。脚本校验商品、授权、流程、附件并冻结输入；失败先修业务资料，不能篡改账本。读取生成的实际 RUN 和槽位列表。
3. 每个 PENDING 槽位先 `start-slot --run RUN --slot 001`。只有命令成功返回 dispatch 文件才允许生图。这一步预留次数并把派发检查点保存飞书。
4. 阅读本次 dispatch。把 prompt 用于真实原生工具；逐个实际提供 reference_images 中的图片文件，说明商品原图/风格/场景各自角色。相对路径相对于当前运行目录，不能把不可读取的路径当已提供素材。
5. 本次调用只生产一个候选。工具可能调整提示词或未返回模型/调用 ID，照实记录；禁止把教程里的模型名当工具事实。若工具只能走 API 或需要未授权的费用，停下，不能继续。
6. 收到实际文件后记录简短工具摘要，包含本次 RUN、槽位、尝试 ID、实际传入素材 ID、输出来源、工具是否报告模型/调用 ID。不要伪造工具输出或写访问凭证。执行 `stage-result`，按实际使用的参考逐个重复 `--used-asset`，无参考时不填。
7. 原生返回多张时只登记本槽位选用的一张，额外结果标为未登记候选另存，不能拿同一个 attempt 同时填多个槽位。原生工具返回 URL/对话附件时，先通过实际允许的导出/下载方式取得文件再登记。
8. `receive`/`stage-result` 校验通过后产生 final 图与生产回执。背景合成使用原图，不再让模型“优化鞋子”。参考图编辑尺寸不符时停止核查，不能悄悄裁掉商品。
9. 每个候选登记后执行 `push --run RUN`，及时回写成图和检查点，降低仅存在本机的时间。完成后停在“待审核”。

命令模式：

```bash
python -m factory prepare --task 实际任务ID
python -m factory start-slot --run 实际RUN --slot 001
# 此处调用当前会话真实原生图片工具，不能用虚构 shell 命令替代
python -m factory stage-result --run 实际RUN --slot 001 \
  --image /实际图片.png --evidence /真实摘要.txt --actual-model not_reported
python -m factory push --run 实际RUN
```

额度耗尽、超时、没有返回文件：把已完成产物 push，保留 STARTED 槽位为结果不确定。`retry-slot` 需要用户确认可能已消耗额度，不能仅凭“没有看见图片”自行重试。不要一次性预留所有槽位再开始调用。

图像检查建议可以写给用户，但不能替人建立通过记录。汇报精确数字：请求候选、实际已登记、待审核、结果未知和剩余允许调用次数。费用未获得可靠账单就报未知。
