# 07 · 官方依据与兼容性

核查日期：2026-09-19。以下为官方文档/官方项目实现。外部能力会变化，部署时仍须以本机 CLI 帮助和真实租户探针为准。

## Codex 原生生图

来源：https://learn.chatgpt.com/docs/image-generation

该页面当前明确写出内置图片生成使用 `gpt-image-2`，计入通用 Codex 用量；大批量可走独立计价的 API。它也说明网页可用性取决于套餐和工作区设置，并说明参考图须明确其作用。

因此本工程不写死“Image 2.5”，不承诺无限张数、不估算用户账单、不以现有订阅等于零成本。实际调用模型没报告时写 `not_reported`。项目没有内置图片 API Client，不会暗中选择付费通道。

## Codex Skill

来源：https://learn.chatgpt.com/docs/build-skills

官方描述 repo 范围 `.agents/skills`，`SKILL.md` 含 name/description，以及显式 `$skill` 调用方式。因此本工程附带项目内 Skill，用户无需手工搬运全局 Skill 文件。当前客户端无法发现时，直接让 Codex 读取该文件也能按提示词执行。

## larkcli 身份与原始 API

来源：https://github.com/larksuite/cli

官方 README 提供 `lark-cli api METHOD /open-apis/... --params JSON --data JSON`、JSON 输出、user/bot 身份，以及成功/失败信封结构。工程兼容 `ok/data` 与旧 `code/data`，检测嵌套错误，不把解析失败当成功。

当前配置允许可执行文件名为 `lark-cli` 或 `larkcli`；名称相同不保证实现相同。你现有安装如果是其他封装或版本，`doctor` 失败时只对现有版本适配，不擅自安装另一套 CLI。

## Base 子系统

来源：https://raw.githubusercontent.com/larksuite/cli/main/skills/lark-base/SKILL.md

官方 Skill 介绍 Base URL 解析、数据表、字段、记录、附件、视图、BaseApp 与 Workflow。此工程主动采用原始 Bitable API 处理数据，使用附件专用快捷命令处理文件；不混淆两套字段 JSON。

原始数据 API 入口：

- https://open.feishu.cn/document/server-docs/docs/bitable-v1/app-table/create
- https://open.feishu.cn/document/server-docs/docs/bitable-v1/app-table-field/create
- https://open.feishu.cn/document/server-docs/docs/bitable-v1/app-table-record/create

这些动态页面在研究环境中未完整返回可读正文，所以原始 API 的实机接受情况仍列为待验证。包内 fake transport 测试验证程序发出的契约与我们声明的结构一致，不等于远端成功。

## 附件精确契约

来源：https://pkg.go.dev/github.com/larksuite/cli/shortcuts/base

核查时可见官方项目 v1.0.96 的源码导出信息，页面明确提示该模块并非最新版本；这里作为已核查的契约依据，不要求把用户安装强制降到这个版本。

`BaseRecordUploadAttachment`：`+record-upload-attachment`，接收 `--base-token --table-id --record-id --field-id --file`，追加附件。

`BaseRecordDownloadAttachment`：`+record-download-attachment`，接收 `--base-token --table-id --record-id --file-token --output`。只给一个 file-token 时，output 可以是具体文件路径。

附件 upload/read scope 与记录/表资源权限都要通过真实探针验证，不能只看能否列出 Base。

## 视图契约

来源：https://raw.githubusercontent.com/larksuite/cli/main/skills/lark-base/references/lark-base-view.md

工程使用 `+view-set-card` 的 `cover_field`、`+view-set-visible-fields` 的 `visible_fields`、`+view-set-group` 的 `group_config`、`+view-set-sort` 的 `sort_config`。画册、看板和排序组合成 V1 的业务界面。并未创建独立 Web App 或自称有任意节点画布。

## 图像处理依赖

来源：https://pypi.org/project/Pillow/12.3.0/

工程固定 `Pillow==12.3.0`，交付环境实际测试版本相同。使用标准库加 Pillow，未打包字体文件或第三方模型。用户安装时仍从其正常包源获取依赖；本包不承诺供应链审计或跨系统像素位级完全复现。

## 启动时保存兼容性证据

运行 doctor 后保存摘要到 `var/live/acceptance/`，记录真实 CLI 版本、Python/Pillow 版本、身份类型、Base 读取、需要的帮助项和附件探针。不要保存凭证、全部环境变量或完整用户通讯录。升级 CLI/更换账号后重复这组验收。
