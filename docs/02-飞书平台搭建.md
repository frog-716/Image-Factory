# 02 · 飞书平台搭建

## 新建专用 Base

在飞书中新建一个空白多维表，建议命名“TOPSTAR 图片工厂 · 验证”。把链接给 Codex，明确允许只在这个 Base 新增本工程表与视图。当前旧“素材库（测试）”不自动迁移、不清空。

Codex 用已安装的 larkcli 核实链接指向的真实 Base。Wiki 链接须先解析，不能把 Wiki token 当 Base token。当前官方 Base skill 提供 `base +url-resolve --url ...`；实际运行先核对本机帮助。

脚本只使用现有 CLI 身份，默认 user。Base token 是资源标识，仍按内部配置处理；不需要把访问 token、Cookie 或 OpenAI API Key 放进多维表。

## 建表与视图

先运行 `bootstrap` 看计划，确认目标后运行 `bootstrap --apply`。它只新增本工程表、缺失字段及关系，不会删除默认空白表，不会改已有字段类型。遇到同名表/同名字段歧义或字段类型冲突停止，交由人工检查。

| 表 | 后台职责（非普通审核界面） | 关键关系 |
|---|---|---|
| 01 商品 | 每个真实 SKU 填一次事实、来源和禁止变化项 | 默认商品原图关联素材 |
| 02 素材与成图 | 直接上传和浏览商品原图、风格/场景参考、Logo、生成成图 | 商品、来源任务、图片 SHA256 |
| 03 流程 | 选择生产方式、版本、画布和商品占比，确认后发布 | 被任务和步骤引用 |
| 04 流程步骤 | 排序、编辑提示词、插入参考素材、启停提示词节点 | 关联一个流程和若干素材 |
| 05 生产任务 | 选商品、流程、场景、版位、数量与调用上限，勾提交 | 对应唯一运行 ID，附件含档案及交付 ZIP |
| 06 人工审核 | 保存 Human UI → Engine API 创建的受信审核事件；普通用户不直接写表 | 图片资产、目标 SHA256、审核人及系统创建人 |
| 07 上架记录 | 人工真实发布后记录位置和时间，不按 SKU 总数模糊归因 | 每次使用固定一张成图版本 |
| 08 效果数据 | 导入原始计数和证据；更正追加版本 | 关联一次上架，保留历史和来源文件 |

精确字段定义在 `templates/feishu-schema.json`。系统创建人/时间由服务端产生，脚本不会伪写。`SHA256` 可以理解为文件指纹，同一文件内容对应同一指纹。

`setup-views` 配置五个后台视图：商品卡片、素材画册、生产看板、按流程编排、审图台。素材画册以图片附件为封面；生产看板按系统状态分组；步骤按所属流程分组、顺序排序。普通审核者使用独立的两页 Human UI，不在审图台填写技术字段。

你可以额外手动建立常用筛选，例如“商品原图”“可用参考”“待审核成图”。这些视图共享相同记录，不要复制成多份独立业务表。系统状态和运行字段只供查看，不要手动拖卡片改变执行状态。

## 入库规则

一条素材记录 = 一个图片文件版本。主图、细节图、白底图、透明图分别建记录。商品卡片“商品照片”可放预览，实际生产读取“默认商品素材”对应的素材记录，预览图与生产图不是双重事实源。

为每张实际使用图片填写：资产 ID、类型、来源说明、授权说明、所属商品（商品原图必填）、图片附件、允许用于生图。来源 URL 只是线索，不能自动证明授权。SKU/品牌/颜色/材料/功能等事实必须来自你确认的资料；缺少事实就明确缺少，不让模型补猜。

商品透明图建议由已有抠图工具处理并人工检查鞋带、孔洞、边缘、半透明区域，再入库。包内未提供自动抠图模型。

示例、自检图必须保留“示例数据”勾选，不关联真实任务。`probe-feishu` 会留下一个明显命名的自检素材记录，用于验证写入、附件追加和下载哈希，不调用生图模型。

## 权限建议

第一轮个人验证：使用你已有 user 登录，在专用 Base 中进行。审核操作留在人手里，经 Human UI 明确确认后才由 Engine API 写入。持有同一用户身份的恶意执行器仍可能伪装该人操作，个人同账号模式不能提供强身份隔离。

团队正式运行：配置独立执行身份。让 Runner 读商品/流程、写任务/成图、只读审核；由受信审核身份通过 Engine API 创建审核事件。字段/表级权限是否可用依租户版本，以实际飞书管理页面为准。脚本不会自动关闭高级权限或把 Base 改成公开。

larkcli 的权限不仅取决于 OAuth scope，还取决于 Base 是否分享给当前身份，以及记录、附件、表结构等权限。先 `doctor`、`schema-check`、`probe-feishu` 实测；403 时只针对缺失权限修正，不批量扩大所有权限。

审核人 open_id 可从已授权的身份信息获取，也可让本人在审核表手工新建一条“审核人登记”记录并选择自己，保持图片资产为空，由 Codex读取该记录的系统创建人及审核人验证一致后登记在 `config.local.json` 的 `reviewer_open_ids`。不得根据显示名猜 ID。登记行不参与成图审核。

## 正式使用不必写代码

改风格、场景、版位、提示词和引用素材：在飞书操作。

改变执行算法、合成位置策略、增加新的生图阶段或新 Producer：修改代码、版本和测试。

两类变化边界分开后，业务人员能日常使用，工程代码仍有清晰可维护的职责。
