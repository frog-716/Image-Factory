# 03 · 从零到一张真实交付图

命令均在工程根目录执行。`REC`、`RUN`、`SLOT` 表示实际返回的 ID，不能直接粘贴占位符执行。推荐让 Codex读取相应提示词并填入真实 ID。

## 1. 打开工程，跑本地演练

```bash
bash scripts/setup.sh
source .venv/bin/activate
bash scripts/test.sh
python -m factory demo --out var/first-demo
```

macOS 可 `open var/first-demo/index.html`；Linux/WSL 用浏览器打开该文件。离线演练中没有真实飞书写入和真实模型调用。依赖只安装到项目 `.venv`，不会修改现有 larkcli 配置。

## 2. 给 Codex 总提示词

读取 `prompts/00-START-HERE.md`。将新建 Base 链接附在同一条消息，明确“允许在这个专用 Base 新增表和视图；旧 Base 不动”。初始化时尚未授权生图。

Codex 应做的命令顺序：

```bash
python -m factory doctor
python -m factory bind --base-token 实际BaseToken
python -m factory doctor
python -m factory bootstrap
python -m factory bootstrap --apply
python -m factory schema-check
python -m factory setup-views
python -m factory seed-workflows
python -m factory probe-feishu
```

CLI 名称有差异时通过 `bind --cli /实际路径/larkcli` 指定，不要安装另一个工具覆盖现有工具。

`probe-feishu` 新建并保留一个自检记录，实际验证文件上传、追加、下载和字节哈希一致性。任一步失败先停在该步，按恢复手册核对远端状态。没有运行成功之前，不得说飞书已经接通。

## 3. 登记审核人

从真实 CLI 身份信息或本人手工创建的“审核人登记”记录获得 open_id。更新配置：

```bash
python -m factory bind --base-token 实际BaseToken --reviewer ou_实际审核人ID
```

重复 `--reviewer` 可登记多人。不要把你不知道归属的 ID 加进去。命令更新本地配置，不会替人写审核结论。

## 4. 放入第一个真实商品

在“01 商品”建立一个 SKU，填真实商品名、品牌、事实版本、已确认事实、禁止改变和事实来源。确实核对后由人勾“资料已确认”。

在“02 素材与成图”添加一张人工核对过的透明商品原图，设置资产 ID、类型“商品原图”、所属商品、来源和授权说明，上传一个文件，勾“允许用于生图”，不勾“示例数据”。回商品表把它选成“默认商品素材”。

再放 0 至若干张可合法使用的风格/场景参考。用同样方式记录来源与授权。没有授权的参考先留作线索，不勾允许用于生图。单张图多个角度和多个商品混杂时先由人选定用于这次生产的单一商品视角。

## 5. 在飞书编辑流程

初始已导入 `[IF] 背景合成 v1.0` 和六个步骤。打开“按流程编排”，前两个提示词节点就是可编辑的说明，可以关联参考素材。

试用前可改草案。流程被任务使用后，需要新版本时复制流程及其所有步骤，更新新流程版本号，确认步骤关联到新流程，再发布。不要仅复制流程主记录而漏掉步骤。

流程选择“背景合成”，先用 1024×1024、商品占比 0.70。提示词中的 `${scene}` 表示照片里的消费场景，`${placement}` 表示图片在页面放哪儿，二者分开。

要用“参考图编辑”，以 `templates/workflow-reference-edit.json` 为草案建立独立版本，先确认允许重画商品风险再发布，步骤里不放“原图合成”。

## 6. 验证 Codex 真的能生图

给 Codex：

```text
执行 prompts/01-SETUP.md 中的原生生图探针。
允许消耗 1 次原生图片生成调用，只画无品牌的简单几何背景。
不得改走 API，不读取或设置 OPENAI_API_KEY，不复用浏览器凭证。
必须拿到实际图片文件和调用证据；记录实际模型，未报告就填 not_reported。
```

成功后由 Codex运行 `record-capability --image 实际文件 --evidence 调用摘要.txt --actual-model 实际模型或not_reported`。探针文件不作为商品素材使用。

这个登记只证明本次本机检查和操作者报告，不是服务商签名凭证。换设备、账户或原生工具方式后应重新探针。

## 7. 下第一张订单

在“05 生产任务”新建记录：选商品、流程、参考素材；填真实渠道、用途“场景广告图”、消费场景、版位、视觉风格。数量 3，最多调用次数 4。

“变体方向”可以一行一个方向，例如“左侧柔光、浅背景”“户外绿植、留白”“暖色室内、近景”。这只是创意要求，不能写不存在的商品功能。

人勾“提交”。此时进入队列，还未开始后台生产。给 Codex：

```text
按 prompts/03-PRODUCE.md 执行我已提交的任务。
使用已验证的 Codex 原生生图能力；严格遵守每个任务的调用次数上限。
完成后把真实成图、回执和运行档案回写飞书，停在人工审核。
不要替我审批，不要自动上线，结果不确定时不要重复生图。
```

机器工作顺序：`queue → prepare → start-slot → 原生工具 → stage-result → push`。每个槽位一张图，串行执行。

## 8. 人工审图

在“素材画册”看成图。放大核对商品外形、颜色、Logo、细节，以及背景自然度、渠道要求和文案。脚本能打开 PNG 并不代表它符合商品事实。

“06 人工审核”每张成图新建一行：选择图片资产，填该图 SHA256，选择本人，填写通过/驳回，勾人工确认；通过还必须勾商品准确、品牌及渠道检查。驳回写原因。

不要直接改素材表的“审核状态”当批准。脚本只认审核表事件。改变既有结论时新增“撤回/驳回/通过”记录，旧记录保留。

## 9. 取批准 ZIP

告诉 Codex“我已审核完成，按 prompts/04-REVIEW-DELIVER.md 同步并交付”。

```bash
python -m factory sync-reviews --run 实际RUN
python -m factory export --run 实际RUN
```

ZIP 上传到任务“已批准交付包”。只收已批准文件；清单明确 3 个候选中实际批准几张。还有未完成/未审核图时默认拒绝完整交付，只有明确授权部分交付才使用 `--allow-partial`。

原始生图、商品源图、冻结提示词和生产回执在“运行档案”，不要把内部档案误当对外图片包。对外包仍含 SKU 和审查记录 ID，外发前按业务保密要求再检查。

## 10. 上架和反馈

由人把批准图用于一个实际渠道。在“07 上架记录”写唯一使用 ID、图片资产、图片 SHA256、渠道、店铺/账户、版位、广告或页面 ID、开始时间和实验/对照说明。确认实际发布后才勾“人工确认已上线”。

同一图片用于两个广告，建两条使用记录。一个广告同时轮播多张图又无法获得单图数据时，不要把广告总数硬分给每张图；记录能力限制，暂不纳入单图反馈。

把后台真实导出数据保留原件，按 `templates/metrics.csv` 映射。第一版允许人工转录真实后台值，但标记 `verified_manual` 并在上架记录附截图或原件；禁止凭空编数。脚本直接保存的是规范化 CSV 原件，渠道原始导出/截图需保留在上架证据。

```bash
python -m factory import-metrics --csv /实际路径/metrics.csv
python -m factory metrics-summary
```

同一逻辑行重复导入不会新增。后台更正数据时保留旧版本，显式：

```bash
python -m factory import-metrics --csv /实际路径/corrected.csv --revision 2 --confirm-correction
```

`metrics-summary` 只返回每个逻辑键的最新版本。点击率=点击/曝光；“每点击订单率”=订单/点击，不能直接当所有平台口径的 CVR。分母为零显示未知。样本提醒只作描述，不能宣称某图带来销量提升。

## 11. 下一轮改进

让 Codex 读取当前 SKU、具体上架版本、同口径最新指标和人工驳回原因，提出 2 至 3 个可验证的新方向。由人选方案，复制任务；商品事实不因为点击率较高就自动修改。

只改变一个主要创意因素更容易比较。渠道、价格、投放人群、时间、预算变化都会干扰结论；没有可靠对照时只记录观察。

交付 ZIP 可再次独立检查，不需连接账号：

```bash
python scripts/verify_delivery.py /实际路径/交付包.zip
```

这个命令验证文件数量和哈希，不会自动授予审批或发布权限。效果表中 0.03 表示 3%；需要时在飞书手动设置百分比显示，不改原始计数和存储值。
