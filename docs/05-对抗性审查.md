# 05 · 对抗性审查与修正记录

## 审查结论

**适合先做单机、小规模、人工批准的真实试产；不能直接当作多人并发、无人值守、强审计保证的生产服务。**

审查按重复花额度、数据造假、错误商品、审批绕过、恢复失效和接口漂移组织。下列修正已经落实到代码；测试文件和实际输出随包提供。测试使用 MockBase/FakeSchemaTransport，未破坏或访问用户真实 Base。

P0：重复成本或错误交付等核心风险。P1：阻断安全、可靠性或追溯。P2：体验与可操作性。优先级代表本工程设计判断，不构成安全认证。

## 已处理的问题

### R01 · P0 · 重复发起原生生成或超时后盲重试，重复耗额度

修正：先预留 attempt；写飞书检查点并回读后才交 dispatch。STARTED 保持不确定，人工确认才可 retry，次数不清零。

位置：`factory/engine.py`。验证：`test_duplicate_dispatch_blocks / test_retry_keeps_budget / test_checkpoint_failure_does_not_reset_slot`。

### R02 · P0 · 本机丢账本后从头跑已有任务

修正：远端已有运行ID即拒绝 prepare；恢复只能使用对应 Base 最新档案 SHA256，已派发状态不回退。

位置：`factory/engine.py / cli.py`。验证：`test_new_machine_must_restore_existing_run / test_restore_preserves_uncertain_slot`。

### R03 · P0 · 上传响应成功却没有真实可见的检查点

修正：上传后读回附件元数据及最新指针；不可见即停止派发。未知写操作只读对账。

位置：`factory/engine.py / state.py`。验证：`test_upload_success_without_visible_attachment_blocks_dispatch / test_unknown_write_never_blind_retries`。

### R04 · P0 · 旧审核套到被替换的图片，或删除撤回恢复旧批准

修正：审核绑定文件SHA256；导出重新下载核对；保留已见审核摘要，事件编辑/删除即阻塞；导出前再读结论。

位置：`factory/engine.py`。验证：`test_remote_attachment_mutation_blocks_export / test_review_deletion_detected / test_revocation_removes_previously_approved`。

### R05 · P0 · 生成图/示例图混成商品事实或正式成图

修正：商品归属、授权、单文件版本、示例隔离、实际 Producer 与回执校验；同图不能占两个槽位。

位置：`factory/model.py / engine.py`。验证：`test_demo_cannot_enter_live / test_wrong_sku_ownership_blocks / test_same_image_cannot_fill_two_slots`。

### R06 · P1 · 飞书数据在执行中被改，结果无法追溯

修正：任务、商品、流程步骤、素材元数据冻结；本地输入与请求哈希每次核查。改动必须新建版本。

位置：`factory/model.py / engine.py`。验证：`test_input_edit_after_prepare_blocks / test_frozen_request_tamper_blocks / test_local_input_tamper_blocks`。

### R07 · P1 · 参考文本诱导执行代码或读取凭证

修正：纯变量替换，无 eval；subprocess argv + shell=False；路径与软链接校验；Agent 外部内容为数据规则。语义提示注入仍有残余风险。

位置：`factory/util.py / model.py / lark.py / AGENTS.md`。验证：`test_business_shell_is_data_only / test_prompt_unknown_variable_blocks / test_no_shell_interpolation`。

### R08 · P1 · 远端创建成功但响应丢失，重跑产生重复记录

修正：journal-before-write；按稳定业务ID读对账；缺少 table_id 的创建响应保留 unknown。

位置：`factory/state.py / sync.py`。验证：`test_reconciles_remote_success_after_timeout / test_bad_table_response_remains_unknown`。

### R09 · P1 · CLI 版本漂移、分页漏读、嵌套错误被当成功

修正：启动帮助/版本检查、完整分页、游标异常停止、兼容信封并检查内嵌错误；真实附件探针。

位置：`factory/lark.py / cli.py / sync.py`。验证：`test_pagination_reads_all_pages / test_repeated_cursor_stops / test_nested_error_not_ignored / test_attachment_probe_roundtrip`。

### R10 · P1 · 部分失败却声称完成全部数量

修正：候选数和实际交付数分别记录；只批准图入包；部分交付须显式授权，拒绝空包。

位置：`factory/engine.py`。验证：`test_approve_reject_package_counts / test_missing_review_needs_explicit_partial / test_no_approved_images_no_zip`。

### R11 · P1 · 账本跨 Base 混用，恢复包写出目标目录

修正：账本绑定 Base；恢复验证归属、文件数/大小、重复路径、穿越、软链接及校验清单。

位置：`factory/state.py / engine.py / util.py`。验证：`test_base_binding_cannot_switch / test_backup_traversal_rejected / test_backup_checksum_tamper_rejected`。

### R12 · P1 · 假反馈、重复导入、数据修订覆盖旧值

修正：来源性质区分；上架ID与图SHA和渠道核对；导入前整批校验；显式更正追加版本，最新汇总。源证据真实性仍由人核对。

位置：`factory/metrics.py / sync.py`。验证：`test_reimport_does_not_duplicate_metrics / test_corrected_revision_preserves_previous / test_batch_validation_before_any_write`。

### R13 · P1 · 零分母产生虚假0或混用CVR口径

修正：零分母返回None；保留原始整数计数；单独命名每点击订单率；无因果结论与爆款标签。

位置：`factory/metrics.py`。验证：`test_zero_denominator_is_unknown / test_raw_counts_and_formula_validation`。

### R14 · P1 · 图片解码过载、目录逃逸或备份无限增长

修正：限制文件格式/像素/字节、拒绝动画/软链接；检查点总大小受配置限制，达到限额停止派发。

位置：`factory/media.py / util.py / engine.py`。验证：`test_corrupt_image_rejected / test_small_and_oversized_image_rejected / test_archive_capacity_blocks`。

### R15 · P2 · 示例目录相对路径导致演练最后一步失败

修正：演练入口统一转绝对目录；HTML 使用相对图片链接，样例 ZIP 路径可随目录移动。

位置：`factory/demo.py`。验证：`完整离线演练与解压后冒烟测试`。

## 尚未彻底消除的风险

**身份隔离不充分。** 个人 user 登录让 Codex 与本人拥有同一身份，程序不写批准记录与审核人核对只能减少误操作。持有同一身份的恶意 Agent 可以绕开约定。团队正式运行应建立独立执行身份、审核表只读与独立人工审核人；本包不自动改权限。

**单机锁不等于分布式锁。** 本机进程锁覆盖单次命令，未在飞书服务端原子领取整项任务。两个电脑同时读取草稿仍可能竞争。V1 要求一个 Base 只由一台电脑、一个 Codex 会话执行；多人自动化必须先增加队列/租约。

**生成回执依赖真实操作者。** 文件哈希、Prompt/素材哈希和调用证据可核对错配，无法单独证明真实模型内部行为或原生调用确已发生。不能把填写了 codex_native 就当服务商签名认证。

**原生能力和预算不可保证。** 原生生图权限、质量、配额、时间、实际模型可能变化。上限控制预留调用次数，未测量订阅机会成本或实际货币账单。无自动 API 后备路线。

**商品忠实度与审美。** 背景合成保留经人工确认的原图作为商品来源，仍可能出现缩放失真、光影不搭或接触不自然。参考图编辑可能改商品细节。技术检查不能替代人审和渠道规范核对。

**版权、肖像和品牌授权。** 来源/授权字段是审计入口，不能自动证明权利真实有效。尤其第三方电商商品图与儿童模特素材，须由业务负责人核对实际使用权；本包没有抓取或提供真实 TOPSTAR 素材。

**反馈归因。** 代码能核对记录关系、时间格式、计数和修订，不能证明后台原件真实、渠道口径正确或图片导致转化变化。上线时间/归因窗口需人工核查，价格/流量/人群变化须记录。

**导出后的撤回。** 导出前双读降低竞态风险，无法阻止最后一次检查之后产生撤回，也无法收回已下载/已发布文件。操作台需要人工跟进撤回与下架。

**最新指针与附件的两次写入。** 飞书附件追加与最新哈希更新不是跨接口事务。失败时程序停止，必须对账。不能声称云备份 exactly-once 或任意灾难自动恢复。管理员同时修改记录与备份也超出校验防护范围。

**API 兼容与容量。** 官方接口/CLI 会变动，初始化包含真实探针。飞书附件配额和完整检查点带来的累计存储要在实际租户验证。原始 API 只有模拟契约测试，真实服务返回有差异时须修适配器。

## 上线判定

交付时仅把离线测试和示例记为通过。用户电脑完成 docs/06 的 B 段后，才能确认飞书接通；完成 C 段后，才能确认一个真实 SKU 跑通。

不把“生成了图”当唯一验收条件。至少要能反查：真实商品与来源、冻结输入、具体调用、成图版本、人工批准、交付文件、实际使用和数据证据。
