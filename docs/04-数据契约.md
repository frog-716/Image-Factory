# 04 · 数据契约与版本

## 业务字段的权威来源

`factory/schema.py` 是建表机器定义，`templates/feishu-schema.json` 是相同结构的阅读/导入参考。不能把 JSON 中的中文标签随意改名后仍期待脚本自动猜字段。

原始 Bitable API 使用数字字段类型和 `{"fields":...}` 包装；larkcli 的部分快捷命令使用另一套字段结构。`factory/lark.py` 负责隔离，不要混用。接口响应、链接数组、系统字段形状发生漂移时停止并适配。

## 人工创建任务的表单边界

飞书表单让普通用户只填写业务内容：`选择商品`、`图片用途`、`消费场景`、`视觉风格`、`数量`、`附加要求`，最后在 `创建确认` 中选择唯一选项 `确认创建演示任务` 并提交。填写商品但未作这项明确确认，不等于授权创建任务。现有技术字段继续留在任务数据层，不作为表单问题。

表单写入的是待受理草稿；它不能自行选择 Workflow、设置图片调用额度或启动 Producer。独立受理进程只在本地受信配置与显式授权同时存在时扫描，且只受理授权商品范围内的一条明确确认记录。Engine 校验商品、素材和策略，冻结输入，自动填写运行 ID、流程关联和技术状态；后续图片派发仍受独立的额度和原生工具协议约束。未确认的商品资料、未核验的透明原图或缺失的批次授权都不能靠表单选择绕过。

## 输入冻结

`source-snapshot.json` 包含任务输入、商品事实、流程和步骤、所选素材的记录 ID 与附件 token/name/size。下载后追加本地文件 SHA256、真实尺寸和格式。

运行 ID 按 Base+任务记录 ID 确定，任务关联关系和版本字段参与输入指纹。状态、错误摘要、输出附件等系统字段不参与输入冻结，避免脚本回写导致自己失效。

素材后续正常修改也会阻塞旧任务，包括授权撤回。处理方式是完成数据核对后新增任务，不能关闭冻结检查。

## 提示词变量

| 变量 | 含义 |
|---|---|
| `${product_name}` | 商品名 |
| `${facts}` | 已确认商品事实 |
| `${rules}` | 商品/品牌禁止变化项 |
| `${channel}` | 渠道 |
| `${purpose}` | 图片用途 |
| `${scene}` | 消费场景，图里发生什么 |
| `${placement}` | 页面或广告版位，图放哪里 |
| `${style}` | 视觉风格 |
| `${requirements}` | 附加创意要求 |
| `${variant}` | 当前候选编号及对应变体方向 |

采用纯文本变量替换，不支持表达式、文件读取、模板代码或函数执行。用 `$$` 输出字面量美元符号。变量内容只替换一遍，其中出现 `${...}` 不会再次执行。未知模板变量直接报错。

提示词节点顺序固定为纯文本拼接；任何风格节点不能覆盖执行权限。步骤关联的所有素材会汇总、去重。背景合成时商品原图保留给合成器，不送入背景生成调用；其余参考图送入原生工具。Logo 参考只用于理解约束，不能在背景阶段直接重绘品牌标识。

## 原生工具协议

脚本发请求 → Codex 调实际工具 → 脚本验收，三步不能省略。

旧 Engine 槽位使用 `start-slot`；独立 V1 Runtime 使用 `runtime-dispatch-next`。两者都必须在调用原生工具前原子预留额度并读取本次 dispatch。旧协议包含 `run_id/slot/attempt_id/prompt/prompt_sha256/reference_images/requested_size`；V1 Job 包含 `run_id/step_id/attempt_id/request_hash/definition/reference_asset`。参考图必须实际提供给工具并记录 SHA256 和用途；不能只把磁盘路径文字写给一个无法读取本地文件的模型。

旧协议用 `stage-result` 接收实际工具落盘图片及真实调用摘要，再交 `receive` 验证；V1 Runtime 使用 `runtime-stage-image`。旧协议的 `--used-asset` 必须逐个列出本次实际发给工具的素材记录 ID。背景合成且没有参考图时该参数应为空；不能假装商品原图也传给了背景模型。

```bash
python -m factory stage-result --run 实际RUN --slot 001 \
  --image /实际工具输出.png --evidence /本次工具摘要.txt \
  --actual-model not_reported
```

有参考图时在命令后重复 `--used-asset rec_实际素材`；有真实调用 ID 再传 `--call-id`。未报告的模型名/调用 ID 填 `not_reported`，不得把文档默认模型当作这次工具报告。

回执记录图像原始文件哈希、最后合成文件哈希、Prompt 哈希、输入哈希、实际 Producer、尝试 ID 和证据摘要。`stage-result` 默认时间是本地登记工具结果的时间，不能用来证明服务商实际生成时间；准确工具时间可保存在证据摘要。底层 `receive` 的 `generated_at` 字段要求带时区。

回执是操作者报告，校验能够发现明显错配、缺图、重复文件与超范围输入，无法独立证明模型确实按完整 Prompt 执行。保留原生调用的可核验上下文，不能伪造密码学可信链。

## 状态和重试

飞书状态是人读的摘要；实际槽位状态以执行账本和最新检查点为准。

```text
PENDING → STARTED → FINALIZED → UPLOADED
           ↓
    结果未知：人工确认可能已消耗额度
           ↓
      PENDING（旧尝试保留，累计次数不清零）
```

生成调用与远端写入是不同的重试问题。`retry-slot` 对图片生成不确定尝试授权；`resolve-effect` 只对远端写入的未知结果授权。两者不能互相替代。

收到回执前每次 `STARTED` 都占用一次允许调用次数。这个数字是保守的调用预留量，不能证明真实账单金额。任务失败不会把费用记成 0。

## 审核事件

普通用户只在 Human UI 查看大图、点击“通过／退回”并明确确认，可选填退回原因；**不填写**图片资产 ID、SHA256、运行 ID、审核策略版本或审核版本。Engine API 根据当前可信 Candidate 和 Runtime 快照自动绑定这些字段，并用已在线验证的飞书 user 身份确定审核人；前端声明的身份或 Demo 安全字段不可信。通过 Demo 时，视觉检查和“仅限演示使用”必须由易懂的确认交互表达，不能被静默勾选。允许审核人列表在本地配置，`审核人` 必须与飞书系统 `创建人` 一致。

同一当前 Candidate 的重复点击、刷新或网络超时不能产生第二条有效审核；过期页面、图片 SHA256 或策略变化必须阻断。Runner 只能消费 Engine 已确认的有效审核，不能让 Human UI 直接写飞书审核表。最新有效审核结论决定能否交付；同时间冲突停止。

同一事件被覆盖或已见事件被删除时停止导出。要更正结论新增事件。此机制没有跨租户事务锁，不能自动收回此前已下载或已发布的旧 ZIP；运营需处理撤回后的实际下架。

## 反馈逻辑键

`使用ID + 日期 + 时区 + 渠道 + 指标口径` 构成逻辑键，`版本` 构成修订版本。相同值重传去重；更正需显式下一版本，旧值和证据保留。

CSV 数量字段只接受原始整数。禁止百分号、NaN、负数或公式；点击必须不大于曝光。订单可大于点击，保留其真实计数但不能把该比率解释为购买概率。

`source_kind` 支持 `platform_export`、`verified_manual`、`demo`。前两者也是操作者声明，代码不能证明原始后台真实性。记录日期必须采用指定时区；自动验证不能代替对上线时间、归因窗口、渠道指标定义和后台修正延迟的人工核对。

脚本有少样本提示，1000 曝光只是工作流提示阈值，不是统计显著性门槛。V1 不计算因果胜率，不贴“爆款”标签，不自动改商品事实。
