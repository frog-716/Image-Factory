## B. 你电脑上的飞书验收

在新建、授权的专用 Base 上，依序完成：

- `doctor` 能发现现有 CLI、需要的子命令并读取 Base。
- `bootstrap --apply` 创建 8 张表；`schema-check` 校验字段类型、选项和关系目标。
- `setup-views` 后管理员可以看到商品卡片、素材画册、生产看板、流程步骤和审图台；普通审核者只需 Human UI 的“待我审核”和“任务与交付”。
- `probe-feishu` 新建明确标识的连接测试记录，验证一个图片附件的上传/下载哈希一致，并验证两个证据附件追加后仍都存在。
- 再执行同一初始化和探针时，无重复表、重复自检记录或重复附件。
- 审核人 open_id 可从真实身份或系统创建人获取；对审批表的权限符合当前使用模式。

只有这些真实命令成功才能勾选 `templates/live-acceptance.json` 的相关项。CLI 命令兼容性检查失败时，优先修适配器并加契约测试；不要绕过文件/审批校验。

## C. 一次真实业务闭环验收

1 个真实 SKU，人工确认的透明原图，授权参考，1 个渠道场景图任务，3 候选，最多 4 次调用。

完成一次原生工具探针，实际产物可落盘且 Codex 能记录工具证据。逐槽位先预留、后调用、后登记；飞书出现成图和回执，任务出现最新运行档案。

本人在 Human UI 看大图后至少批准一张、驳回一张；Engine API 自动绑定版本与策略，不让用户填写技术字段。导出 ZIP 的图片数必须等于实际批准数，文件哈希与飞书一致。修改已批准成图附件后导出必须失败，不能继续使用旧批准。

人工上架一张批准图，建立使用 ID；回填真实计数及原始证据。重复导入不增加逻辑行；更正追加修订版，汇总只看最新。此时才算真实业务闭环通过。

## 故障处理

| 现象 | 正确动作 | 禁止动作 |
|---|---|---|
| CLI 401/403 | 检查现有身份、指定 Base、附件/字段权限，只修缺失项 | 重置登录、公开 Base、关闭高级权限 |
| CLI 找不到命令/JSON 不兼容 | 保存版本和相关帮助，集中修改适配器并复测 | 猜参数、用空数组替代失败结果 |
| 飞书写入超时 | `status` 看 unknown_remote_writes；先只读查目标 ID/附件 | 立即重复创建、上传 |
| 原生工具额度不足 | 停止派发；保留已完成图和不确定槽位 | 自动换 API、伪造一张图填槽 |
| 原生工具调用后无文件 | 查原生会话，尝试找到真实输出；没有就停 | 默认认为未收费再画 |
| 提交后用户改了素材/流程 | 新建任务或新流程版本，保留旧冻结记录 | 改本地快照或关掉 guard |
| 审核不通过 | 原任务保留驳回，复制新任务并关联返工来源 | 覆盖原图片与审核行 |
| 审核撤回 | 新增撤回事件；停止后续导出，人工处理已发布位置 | 删除撤回记录恢复旧批准 |
| 备份过大或飞书容量不足 | 停止派发；核对剩余容量，减少后续任务规模或批准存储升级 | 跳过备份继续花额度 |

未知写入的正常恢复是：读取远端找到已创建记录，程序自动对账；由于短暂可见性延迟没有找到时先等待用户下一次重试读取，不得立即假定不存在。

只有人在确认远端没有执行后才能：

```bash
python -m factory resolve-effect --key 'status 返回的真实effect键' --confirmed-absent
```

执行这一命令后也必须重跑原来的业务命令，不能手动乱补结果。

原生生图人工重试：

```bash
python -m factory retry-slot --run 实际RUN --slot 001 \
  --reason '已核查工具会话，无法获得有效结果；接受这次可能已消耗额度' \
  --ack-possible-charge
```

随后才能再次 `start-slot`。总预留次数仍然递增。

## 电脑丢失或状态目录不可用

用原配置映射同一 Base，选择新的、空的 `--state` 目录。不要直接重新 `prepare`：飞书已有运行 ID 时程序会拒绝，避免重复派发。

从任务“运行档案”下载与“最新档案SHA256”匹配的附件。使用真实附件 token 下载，不用过期临时 URL，不选看起来“比较新”的旧包。

```bash
python -m factory --config config.local.json --state var/restored restore --archive /实际路径/最新运行档案.zip
```

恢复命令核对远端运行 ID 和最新档案哈希，再检查归档路径/软链接/重复名称/校验清单/Base 归属，禁止覆盖已有运行。已派发但没有回执的槽位仍保持不确定，不会自动重新生成。

检查点上传成功但“最新档案SHA256”回写失败时，系统可能留下未成为最新指针的附件。人工核对飞书附件、调用证据与账本后才能处理，不能擅自回滚到旧检查点。完全丢失最新状态且不能确认是否已生图时，安全结果是停止并核对，而非猜测执行。

恢复不含 CLI 凭证和整个工作区代码；保留本交付包、非公开配置备份以及飞书访问方式。授权信息在你已有 CLI 安全存储中单独管理。不要把登录目录打进运行档案。

## 恢复能力边界

本版单机锁只保护一次本地脚本进程，不提供多电脑分布式锁。跨电脑并发可能突破领取任务边界，正式多人执行前需引入事务队列/任务租约服务。

备份校验保证内容一致性，不是防恶意管理员重写全部文件的签名。远端审核和最终导出之间仍有竞态窗口；代码做双读检查并降低风险，无法撤回已经发出的文件。
